# Sakura — Outliner-Centered Personal Productivity Workspace

Sakura is a single-file, browser-based outliner that's grown into a full personal productivity workspace: notes, plans, and documents live as a nested tree at the center, with tasks, diagrams, remarks, and Q&A woven directly into it via backlinks and cross-references rather than bolted on as separate disconnected tools. It runs entirely client-side and stores its data locally in the browser by default — no install, no build step, no account required. Signing in (optional) syncs everything to your own account so it follows you across devices, and lets you share individual documents with other Sakura accounts. Optional AI features (rewrite, outline generation, and similar) are opt-in too: use **Sakura Hosted AI** by signing in (no key needed, daily quota), or bring your own key for one of seven built-in providers.

## Overview

Sakura is a single `.html` file. Open it in a browser and it runs — no install, no build step, no network dependency for core functionality. All documents, folders, To-Dos, and settings are stored in the browser's local storage, scoped to that exact file.

Key capabilities:

- Nested outline editing with indent/outdent, drag-and-drop reordering and nesting, duplication, and multi-select
- Bold, italic, underline, strike, highlight, and text color formatting per node
- Heading 1–6 per node, applied independent of tree depth, carried through to PDF export
- Lightweight semantic styling via plain-text conventions: `[Section]`, `(note)`, `!alert`, `` `code` ``, a leading `Label: ` (bolds the label), and `SAP Note 12345`/`OSS Note 12345` (auto-links to me.sap.com)
- Fold/unfold subtrees, with a "+N hidden" badge that's clickable to expand
- `#tags` on nodes, `[[@mention]]` backlinks between nodes, and a "Focus" mode to zoom into one branch
- Inline objects per node — Notes, Discussion (remarks and questions), tables, Images (screenshots, with a built-in markup editor for rectangles, arrows, highlights, and text labels), and draw.io Diagrams — kept directly under the node they belong to
- Tables that can show as a table, chips, cards, charts, progress bars, a timeline, a status board or pros & cons; typed columns (status, date, person, currency with any ISO currency), heat-maps and tick/cross icons — all carried through to the PDF
- **To-Dos** — one app-level task list (with subtasks, due dates, priorities, and repeats) shared across your whole workspace, independent of any single document, reachable from one button in the app bar
- Diagrams — add a draw.io diagram to any node (right-click → Add diagram…, or Generate diagram for a rough first draft from that branch); embeds as a real picture in PDF exports; click a diagram's picture to **preview** it in a large window (scroll or pinch to zoom, drag to move, **Fit** / **100%**, Esc to close) and **Edit** there to open it in draw.io
- Optional AI features — generate an outline from a topic, and rewrite nodes, selections, note/remark lines, and To-Do tasks/subtasks (manually or automatically as you type) — either zero-setup via **Sakura Hosted AI** (sign in, no key needed, daily quota) or bring your own key with any of seven built-in providers
- Quick Assist: a combined command bar and search box (plain-English toggles like "hide file explorer," plus search across documents, notes, tags, to-dos, and settings)
- In-document search and a global header search across settings, help, documents, and To-Dos
- Folders in the file explorer, with drag-and-drop filing and nesting
- Export to **PDF** — always the whole document (folded sections, notes, Q&A, and remarks included), with a table of contents (with page numbers), an optional cover page, and your chosen accent color (independently toggleable for consistent branding when sharing) — or to **OPML**; import from OPML. Copy nodes with Ctrl/Cmd+C and paste them into another document or app
- Multiple documents open as independent tabs
- Theming: Light/Dark theme with an optional System auto-theme, and six accent colors
- Zen mode: a fullscreen, distraction-reduced editor that keeps the app bar and status bar in view
- Installable as a desktop/mobile app (PWA) in supporting browsers
- Manual full-data backup to a file (and restore, with one-step undo); signed in, your data also syncs to your account automatically
- Optional account sign-in (Google or email) syncs documents, folders, To-Dos, and settings across devices, and lets you share individual documents with other Sakura accounts as viewer or editor
- Version History for documents and the To-Dos list — periodic snapshots you can restore from independently of the undo stack (the last 10 per document, the last 5 for To-Dos)

## Core Editing

- **Enter** — new sibling node below; **Shift+Enter** — split the node at the cursor (text after the cursor becomes a new sibling below); **Ctrl/Cmd+Enter** — new child node
- **Tab / Shift+Tab** — indent / outdent the selected node
- **Backspace** at the start of a row merges it into the row above; **Delete** at the end of a row pulls the next row up into it. The merged-away row's note, tables, images and tags move onto the row that stays, and any Q&A, remarks, diagrams or to-dos linked to it follow along (one **Undo** splits them apart again)
- **Drag a row** — drop above/below to reorder, or onto the middle of another row to nest it as a child
- **Right-click a node with children** — sort children A→Z, Z→A, or by depth. To sort the whole document's top-level nodes the same three ways, right-click the open document's **tab** — the same tab menu has **Version history** (also the **History** chip in the line under the title: a small menu with the last 5 versions to restore — restoring first saves a "Before restoring" version — **Save a version now**, and **All versions…** for the full window) and **Clear all nodes** (asks first; Undo brings everything back)
- **Toolbar** — one fixed bar above the editor, always shown (zen mode hides it), in unlabeled groups: **Undo, Redo · Outdent, Indent · Bold, Italic, Highlight (with its colour picker), Text colour (with its picker), Heading style · Insert ▾ · AI ▾**, where **Insert ▾** holds everything you add to the selected node under four headings — **Basics** (Note, Checkbox, Tags, Date/time), **Marker** (one row of the five marker icons; click the active one to clear it), **Discussion** (Question, Remark) and **Visuals** (Table, Image, Diagram, Generate diagram), with the right-click menu's More section using the same headings, groups and order — and **AI ▾** holds Rewrite node and Generate outline, with **Collapse all + Zoom** as a small pair at the right end. It wraps onto a second row on a narrow window. There's nothing to customise
- **Row icons** — a row's marker, its note/thread/diagram/table/image/To-Do dots, the folded "+N" count and its tags sit right after the text, at the end of the last line when the text wraps, so it is clear which row they belong to. They grow with Settings → Text size.
- **Right-click a node** — marker icons, a quick row (by default Rewrite, Note, Thread, Add diagram, Add table, Add image), and **More** for everything else. Below the quick row, **More** is kept short: **Add** (child / above / below / duplicate) and **Move** (up / down) are one row of icons each, like **Sort children**; anything you can add to a node that isn't already in the quick row sits behind one **Insert ›** flyout (with the toolbar's Basics / Discuss / Visuals headings); what acts on the row and its branch (Zoom in, Collapse/expand, Tags, Version history, Leave out of export) sits behind **Row ›**; then Delete. The quick row is yours to arrange: drag an icon onto another to reorder, right-click an icon to move it, remove it or **Reset quick row**, and hover any More item for its pin button to add it (up to six icons). Your order is saved with your preferences — Insert above/below, Add child, Duplicate, Zoom in, Move up/down, Collapse/expand, Sort children (one compact row of three icons, shown only when the node has children), then things you add (Generate diagram, Insert date/time), then things you look up (Tags, Version history), Leave out of export, Delete
- **Open items summary** — the editor toolbar's right side says what still needs attention in the document, in words: "6 follow-ups · 2 questions · 1 remark" (open follow-ups, each Follow-up entry counted on its own, open questions, open follow-up remarks; folded branches included); it hides when nothing is open. Click it for the list: each open item grouped by kind — open items only: Agreed and Out of scope rows aren't listed (their markers show in the outline); under each follow-up, the thread line that set it says why it's open (not a later reply); under each open question, the row it's on and who asked. Each item shows how long it has been open on the right ("today", "3d", "2w", "4mo"; a follow-up counts from the entry that set it). Click an item to jump to it (its branch unfolds). To filter the outline: the **Filter outline** switch beside the title shows only rows with something open (click it again to clear); it is the one filter. The **copy** button before it copies every open item as a numbered agenda, dated ("As of 21 Oct 2026"; follow-ups with their section, owner, "since" date and the line that set it, plus "waiting on open question N" when a later line is one of the questions; open questions with their row, who asked and when), as rich text for email and docs with a plain list fallback. For the PDF, Settings › Export & copy › **Open items page** (off by default) adds the same list after the Contents, each item with the page it's on; rows left out of the export stay off it, and with nothing open there is no page. Any filter (open items, a marker, a tag) unfolds the branches hiding its rows and folds them back when cleared, so the outline returns to how it was. Opening another document clears any filter. Rows that share a name say where they are on the grey line ("in Exclusion Scenarios · …"); the same name under the same parent is numbered ("Export (2)"). Shortcut: **right-click** (or **Shift+click**) the summary to turn "Show only open items" on or off without opening the list. **Decisions** have their own chip beside it ("2 decisions", shown only when there are some): click it for what was decided in threads, on which row and by whom; click one to jump to it.
- Click the fold arrow to collapse or expand a subtree; when collapsed, the "+N" badge is itself clickable to expand, and turns your accent colour when open questions or follow-ups are hidden inside (clicking an accent count also opens the first of them); its tooltip says what is inside, with counts ("2 diagrams, 1 table, 1 open question, 1 follow-up; also a note…"). It shows no icons, so it never competes with the row's own dots. Messages that offer Ctrl/Cmd+Z to undo stay up for 4 seconds
- Use `[Text]`, `(Text)`, `!Text`, and `` `Text` `` inline for section labels, muted notes, alerts, and inline code
- A node or note starting with `Label: ` (any short word/phrase before the colon) bolds the label — e.g. `Customer: Acme Corp` bolds "Customer:". `SAP Note 12345` or `OSS Note 12345` (a 5–10 digit number) auto-links to that note on me.sap.com
- Hover a row's tree connector or dot to see when the node was created and last modified
- **Checkboxes** — toolbar Insert ▾ → Checkbox, or type `[ ] `/`[x] ` at the start of a node while editing (auto-converts on commit). Click the box to check/uncheck; checked nodes show struck-through, dimmed text. A checkbox parent with checkbox children shows a live progress badge (e.g. `2/5`) and auto-checks itself once every child is checked
- `Ctrl/Cmd+Space` opens **Quick Insert** — a small menu for inserting an em dash, en dash, arrow, checkmark, cross mark, middle dot, or date/time without leaving the keyboard. Same menu, same shortcut, in every editable area of the app (nodes, inline notes, threads, To-Dos, the title field) — not just while editing a node

## Documents & Tabs

Sakura supports multiple open documents at once, shown as tabs above the toolbar — similar to browser tabs.

- Clicking a document in the file explorer, or the **+** at the end of the tab strip, opens it as a tab
- **Each tab keeps its own undo/redo history, scroll position, and selection independently.** Switching tabs does not reset undo history the way switching documents used to
- **Double-click a tab** to rename it
- The **X icon** on a tab closes the tab only — the document itself is not deleted and remains in the file explorer
- The **dropdown arrow** at the right of the tab strip opens a searchable list of all open tabs (arrow keys + Enter to jump, or click a result) — useful once you have more tabs open than fit on screen
- **"Reopen tabs on launch"** (toggle via Quick Assist — no Settings UI control for this yet) controls whether your previously open tabs come back automatically, or whether each session starts with just one

## Inline Objects

Beyond the text itself, richer content attaches to a node as inline objects shown directly under it in the outline — there are no separate floating or docked panels for them (earlier versions had a side Pad panel, a floating Note/Code panel, Decision Log, Notepad, Mind Map, Files, and Preview/Presenter mode; all were removed to keep the app focused on its core outline workflow).

- **Order under a row:** note, then tables, images and diagrams, then the thread last — the same in the outline and the PDF, so the conversation follows the content it's about.
- **Note** — every node can hold a note, shown inline directly under the node (a small dot marks a node that has one; click it to expand or collapse). Add or edit it via right-click → Note…, the toolbar, or `Ctrl/Cmd+Shift+N`; edit it in place, and right-click a note line to Rewrite it with AI or delete it. **Links in a note:** paste a link and it keeps its title (as SharePoint's "Copy link" gives it); paste a bare web address and it becomes a link (over selected text, it links that text). Click a link to open it, or Ctrl/Cmd+click while you're editing the note; hovering shows the address. Right-click a link to Open, Copy, Edit or Remove it (Undo reverts an edit).
- **Inline threads and Diagrams** — two kinds of object that live directly under the node they're about, in the outline itself (there's no separate side panel or list view for them). Each node shows a small dot when it has any; click the dot to show or hide them inline.
  - **Thread** — every node has one thread: the conversation about it, a flat list in time order (oldest first). Each entry starts with an icon, in a small tinted circle, saying **what it is** — a question (accent colour while open), an answer (✓ Yes / ✗ No, or a reply arrow ↳ for an answer without Yes/No; the line then says "· yes", "· no" or "· answer" quietly), a decision (handshake), a status such as Follow-up (its marker icon), or a plain comment (a faint speech bubble; not a dot, since rows use dots) — then one **author**, whose name has their own colour in the document, the **time** it was written, and the text, and is a **Comment** or a **Question**. Right-click a node (or Insert, or **Ctrl/Cmd+Alt+M**) → **Thread…** opens a new line at the end of the thread; Enter adds the entry, **Ask** (shown while typing) makes it a question, Esc closes it, and a draft is kept when you move on. At rest there is no input line; hover the thread for **+ Add to thread**. The new line writes as the last author used; click the name to add as someone else (e.g. a colleague in a call), or take a name off that list. Right-click the line to add it, make it a question, rewrite it with AI or close it; Backspace on an empty line closes it and returns to the end of the row's text.
    - The thread is grey; only an **open question** (its icon and the row icon's count) takes your accent colour. A **question** is answered by a reply, and the thread stays in time order: right-click the question → **Answer** opens the reply line linked to it (whatever you type is the answer); or press **Yes** / **No** on the reply line (plus any text; a bare Yes/No is one line). When the thread has two or more questions, the reply line shows **to: ‹question› ▾** so you pick which one. The reply line's buttons come in three groups, each with the icon of the entry it adds: **Ask** · **to: … / Yes / No** (when there's a question) · **Follow-up / Agree / Out of scope**. Click an entry's name to pick its author from the names in the document, or **Someone else…** to type one. Pasting into a thread keeps bold, italic, links, lists and line breaks and drops fonts, sizes and colours (e.g. from Outlook or Teams). Right-click an entry → **Mark as the answer** (one question) or **Answer to ›** (several) links it, moves a wrong link, or **Not an answer** removes it. A question can have several answers (e.g. from different people); plain text typed without linking stays a comment. Right-click → **Won't answer** closes it without one. A settled question reads "· question, answered" in grey, and an answer a few entries after its question quotes it ("↳ Does it…").
    - **Status** — Agreed, Follow-up, Out of scope — is quiet text ("· agreed") on the entry that set it (right-click an entry, or Follow-up / Out of scope / Agree on the reply line, which add an entry by the current author). The thread's status *is* the row marker, the one place it is shown in colour. **Each Follow-up entry is its own open item**, like a question: it stays open until right-click → **Mark follow-up done** ("· follow-up, done"; **Reopen follow-up** takes it back) or a later Agreed / Out of scope settles every open one. The row shows Follow-up while any is open; otherwise the latest Agreed / Out of scope is its status. The reply line always offers Follow-up, so a thread can hold several; the open-items count, the list, F8 and the folded "+N" count each one. Clicking a marker records it in the thread by the current author (Follow-up also opens the reply line to say what's left); clearing it takes it back (every open follow-up, for Follow-up). Clicking the marker badge on a row opens its thread at the entry that set it (Shift+click filters the outline by that marker). Older documents: Issue reads as Follow-up, Parked and N/A as Out of scope, Resolved as Agreed.
    - **Follow-up → To-Do** — right-click the entry that set a Follow-up → **Add to To-Dos**. It adds a task with what the follow-up says (or the row's text when it says nothing), its owner as an @mention ("Ana Lee" → @Ana-Lee), linked back to the row. Under its title the task shows who raised it and where it points — "From Ajay · Delivery rules › Fixed delivery days" — and clicking that line goes to the row with its thread open at that follow-up. The entry then shows "· in To-Dos"; click it, or right-click → **Open in To-Dos**, to see the task (each follow-up gets at most one open task). Finishing the task doesn't change the document: the follow-up shows "· To-Do done" and stays open until someone marks it done. Clicking anywhere on a linked task's "From … · Doc › Row" line goes to that row; it never opens the task. In the open task the Link row shows the same line (click to go there) and a pencil to change the link.
    - **Links in an entry** — a pasted web address becomes a link (pasted rich text keeps its links; select text and use the formatting bar's Link to add one). Click a link to open it, or Ctrl/Cmd+click while editing the entry; right-click it to open, copy, edit or remove it.
    - **Copy thread** — right-click the thread's "Thread · N" header, or any entry, → Copy thread. It copies the whole thread with the row name, each entry's author, time and quiet notes (open question, yes, follow-up for…, decision) and its text. It goes on the clipboard as rich text (names bold in their colour, each entry's kind as a coloured symbol — ✓ ⚑ ? 🤝 — notes grey, formatting kept; email and chat apps drop the app's own icons) and as plain lines, so Ctrl/Cmd+V keeps the formatting and Ctrl/Cmd+Shift+V pastes clean text.
    - **Decision** — right-click the entry where something was decided → Mark as decision, or type a new entry and click **Decision** on the reply line (next to Ask): a Decision chip (handshake icon) on that entry (editor and PDF), and the thread header says "· Decision" (click to jump there). It doesn't change the row.
    - A thread longer than four entries shows its latest three; the header's "show N earlier" shows the rest. The PDF prints the whole thread as a transcript under its row (a "Thread · N" header, the entry icons in a column joined by a faint line, names in their colours (no side bar), the date once per day, status as text once — the row's marker carries it); the outline shows it the same way, under the two-speech-bubble row icon. An entry emptied and left is removed.
    - Older documents open converted: Q&A linked to a row becomes a question in its thread with the answer as a reply; follow-up items become statuses and decisions become Decision chips, and markers are lined up with them. Q&A section headers and unlinked questions stay in the Q&A list and print in the PDF's closing Q&A section.
  - **Deleting a row deletes its inline objects with it** — its note, tables, images, thread entries and diagrams (and those of every row under it). Delete only asks when part of it can't be undone: diagrams live outside Undo, so deleting one asks first, with a red warning that it'll be permanently deleted. Everything else goes straight away — the toast names what went ("Deleted 1 node with 1 note and 2 comments") and Undo (Ctrl/Cmd+Z) brings it all back. Backspace on an empty row works the same way. Linked to-dos are kept in To-Dos, just unlinked (and relinked if you undo). Clear all nodes always asks and says what goes. Opening a document also removes, once, any Q&A, remarks or diagrams already left without a row (older documents could hold some), since nothing could show them.
  - **Duplicate and copy/paste bring everything along** — a duplicated or pasted row gets its own copies of its note, tables, images, thread entries and diagrams (same content and status, new ids), and the copy toast says what came with it ("Copied 2 nodes (incl. 1 diagram, 3 questions)"). Diagrams live outside Undo, so undoing a duplicate or paste leaves its copied diagram behind until the document is next opened.
  - A row's thread dot shows how many questions are still open. The toolbar's open items summary counts open questions and follow-ups (markers) too; its list jumps to each one, or shows only the rows holding open ones (filter bar chip to clear it).
  - Notes, discussion items, diagrams, and images are always included in PDF exports — a node's items in one "Discussion" card, each question with its answer (Yes / No in bold) and pill, each follow-up and decision with its pill — and in Version History. Blank items never print.
- **Tables** — a node can hold tables directly under it, shown as a table or as chips, cards, charts, progress bars, a timeline, a status board or pros & cons; see [Tables](#tables).
- **Images** — screenshots and pictures belong to a node as their own objects (`node.images`), not inside its note; a node can hold any number. They show as a compact, wrapping row of thumbnails directly under the node, each with its caption (truncated) beneath, and a small picture dot on the row folds or unfolds them (a folded branch's "+N hidden" badge mentions images inside it).
  - **Adding:** paste a screenshot (`Ctrl/Cmd+V`) while the node is selected, being edited, or its note line has the cursor; drop image files onto the node; or right-click → **Add image…** (under "More" by default; several files at once). Pasting never puts a picture into the note text any more.
  - **Compression:** every newly added image is downscaled to at most 1600px on its long side and saved as WebP at quality 0.8 (JPEG on a white background where the browser can't encode WebP); the original is kept instead only when it needed no downscale and is already smaller. SVGs and animated GIFs are kept byte-for-byte. This keeps documents under the cloud sync's 1MB-per-document limit — a typical retina screenshot drops from several hundred KB to a few tens of KB.
  - **Quick edits in place:** click a thumbnail's caption to edit it right there (**Enter** saves, **Esc** cancels). Right-click a thumbnail for **Open**, **Add/Edit caption**, **Size ›** (Auto, Small, Medium, Full — the current one checked), **Mark up…** (opens the viewer straight in marking mode), **Move left / right**, and **Delete image**.
  - **Viewer:** click a thumbnail for the enlarged viewer — the full picture, its caption editable right under it, **←/→** (or the side arrows) to step through that node's images, **Esc** or a click outside to close. Its **Auto / Small / Medium / Full** control sets the image's display size (natural size up to full width, or 35% / 60% / 100% of the available width), used in the viewer and in PDF exports. Delete from the viewer or from a thumbnail's right-click menu (Open, Edit caption…, Move left/right, Delete image); drag a thumbnail onto another to reorder. Every change is undoable.
  - **Carried everywhere a node goes:** undo/redo, autosave, Version History, cloud sync, backup/restore, Duplicate, Backspace/Delete-merging two rows (the absorbed row's images move onto the surviving one, along with its note and tables), and Ctrl/Cmd+C → paste into any Sakura document. PDF exports show each image as a captioned figure under its node at its chosen size; OPML has no place for images, so they're left out of it.
  - **Older documents:** pictures that earlier versions kept inside a note move into the node's images automatically the first time the document is opened, in their original order (the note's text stays exactly as it was; an image's alt text becomes its caption unless it's just a file name). They're moved as-is, never re-compressed. An `<img>` whose source can't be kept (a temporary `blob:` URL, a relative path) is left in the note untouched.
  - **Marking up:** in the viewer, **Mark up** (or `M`) opens a second toolbar for marking up a screenshot without changing the picture itself: **rectangle** outlines, **arrows**, a translucent **highlighter** (a marker-style box at about 35% opacity), and **text labels** (drawn with a contrasting outline so they read on any background). Drag on the picture to draw (mouse, pen, or touch); with the text tool, click where the label goes, type, **Enter** to place it or **Esc** to cancel; double-click a label to edit it (empty it to delete it). The **select** tool picks a mark to drag it elsewhere, nudge it with the arrow keys (Shift for bigger steps), recolour it from the palette, or delete it (**Delete**/**Backspace** or the toolbar's bin). Six fixed colours — red, yellow, green, blue, black, white — chosen to show up on light and dark screenshots. The editor has its own **undo/redo** (`Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z` or `Ctrl/Cmd+Y`, or the toolbar arrows) and **Clear markings** (asks first). Tool keys while marking: `V` select, `R` rectangle, `A` arrow, `H` highlighter, `T` text. **Esc** steps back one level at a time — cancels a drag, drops the selection, leaves marking mode, then closes the viewer — and the arrow keys never jump to another image while you're marking. Once you're done, the whole marking session on an image is a single step in the document's own undo (`Ctrl/Cmd+Z` in the outline).
  - Marks are stored as shapes alongside the image (`annotations`), with positions relative to the picture's own size, so they stay exactly in place at any display size (Auto/Small/Medium/Full, any window width). They show in the viewer, scaled down on the thumbnails, and over the picture in PDF exports; they travel with the image through undo, Version History, sync, backup, Duplicate, and copy/paste. In a document shared with you as view-only, marks are shown but can't be changed.
  - Images are stored in the document itself (no external storage).

## Tables

A node can hold tables directly under it. Right-click a node → **Add table…** (or Insert ▾ → Table) opens the **Table** menu: **Blank table…**, or **Start from** a table already shaped for a display — Status board (Item · Status · Owner · Due), Timeline (Date · Milestone · Note), Cards (Metric · Value · Change), Progress bars (Workstream · Done %), Pros & cons, Codes (chips) and Bar chart. Each menu line names the columns it makes; a starter shows as its display straight away with sample rows to type over (double-click it to edit the data), so you can see what shape each display needs. **Blank table…** opens a small size picker: hover (or use the arrow keys) to choose up to 8 columns × 8 rows — the readout shows "columns × rows" — then click or press **Enter** (**Esc** cancels). The new table has a header row and opens for editing with its first header cell selected, so you can just start typing. Click a table to edit its cells in place; the columns keep their widths while you edit, and **Esc** or a click outside returns to the normal display. Each editing session is a single **Undo** step.

### Adding and editing

- **Cell menu** (right-click a cell while editing), grouped into short submenus: **Insert ›** (row above / below, column left / right); **Move ›** (row up / down, column left / right); **Sort ›** (A → Z / Z → A) by that column — numbers sort by value ("10" after "9", including `%`, currency like `$1,200`, negatives and `(1,234)`), dates by date (`Oct 14`, `14 Oct 2026`, `2026-10-14`), other text naturally, and empty cells always last; **Turn header row on / off** (the first row becomes or stops being the table's header — sorting and moving rows never move a row into or out of the header); **Align column ›** (Left / Center / Right / Automatically, the current one checked); then the display options (Show as, Heat-map, title, size); then **Delete ›** (row / column / table — undo brings a deleted table back). Anything that doesn't apply is greyed out.
- **Rows and columns:** while editing, hovering a row shows a small grip at its left, and a column shows one above it. Click a grip to select that row or column and open its menu: insert above / below (left / right), move, or delete. Shift+click another grip to select several, then delete them together.
- **Selecting cells:** drag across cells, Shift+click a cell, or Shift+↑ / ↓ (← / → from the start or end of a cell) to select a range. **Delete** / **Backspace** clears the selected cells (or deletes the rows / columns when whole ones are selected with their grips), **Ctrl/Cmd+C** or **X** copies the range so it pastes into Excel or Google Sheets, right-click offers **Clear**, **Delete N rows** and **Delete N columns**, and **Esc** clears the selection.
- **Undo while editing:** **Ctrl/Cmd+Z** steps back through every change made while editing (typing, inserting, deleting, moving, sorting, pasting) and **Ctrl/Cmd+Shift+Z** or **Ctrl+Y** steps forward, without leaving the table. After you finish, one Undo still reverts the whole editing session.
- **Keyboard while editing:** **Tab / Shift+Tab** go to the next / previous cell (wrapping across rows; Tab in the last cell adds a row), **Enter** goes to the cell below (in the last row it adds a row), **Shift+Enter** starts a new line inside the cell (a line break or spaces left at the start or end of a cell are dropped, so they never grow a row or shift a value), **↑ / ↓** move to the cell above / below when the caret is on the cell's first / last line, **Esc** finishes. Tab never leaves the table while you're editing it.
- **Paste from a spreadsheet:** copy a range in Excel or Google Sheets and paste it into a table you're editing — it fills the cells starting at the caret and adds rows and columns as needed (one Undo step). Plain text pastes into the cell as usual. Pasting a copied table onto a row — selected, or while you're typing in it — adds it to that row as a new table instead of splitting it into rows.
- **Selecting rows:** click a row's bullet to select it (Shift+click another bullet to select the range, Ctrl/Cmd+click to add one), or press Shift+↓ / Shift+↑ at the end / start of the text you're typing to carry on into row selection. While several rows are selected a small pill at the bottom says how many, with Copy / Delete / Indent shortcuts and an Esc button.
- **Alignment:** a column whose cells are all numbers (amounts, percentages, currency) is right-aligned automatically; set a column's alignment yourself from the cell menu. Alignment looks the same in the outline, while editing, and in the PDF.
- **Column types:** while editing, right-click a cell → **Column type ›** sets that column to **Automatic** (the default: numbers right-align, a column headed Status gets pills), **Text** (no guessing), **Number**, **Date**, **Status**, **Person** or a **currency**: the menu lists five (your recently used ones first, else EUR, USD, GBP, INR, JPY) and **More currencies…** opens a searchable list of every currency (type a code, name or sign — `dkk`, `danish`, `kr`). A currency column rewrites its numbers as currency (`1234.5` → `€1,234.50`, `DKK 1,234.50`, `CA$5.00`) when set and whenever you leave a cell or paste. Clicking a cell in a Status column offers Open / In progress / Blocked / Done plus the column's own statuses. In a Date column you get a date input with **Today** and **Clear**, and the picked date is written in the same style as the column's existing dates. Number and currency columns right-align. A Status-typed column shows pills whatever its header, and it is the column the Status board uses. **Person** shows each name as a coloured chip (the same colour for the same person everywhere; `Ana, Raj & Mo` is three people) — automatically for a column headed Owner, Assignee, Who, Responsible or Lead — and while editing, clicking a cell offers the people already named in the column. On the Status board, owners get an initials avatar.

### Ways to show a table

- **Show as ›:** right-click a table (or a cell while editing) → **Show as ›** picks how it displays: **Table**, **Chips**, **Inline** (a two-column code/description table as one running line — `ZN` Night Distribution · `ZL` KL 10:00 Fixed — codes in a small accent-coloured monospace, descriptions muted and a size smaller, so it reads as a code list rather than row text), **Cards**, **Row cards** (one card per row in a grid — the first column as the card's title, a short second column as its subtitle, every other column as a labelled field, formatting kept; for wide tables whose rows read as records; only ever chosen here, never automatic), **Progress bars**, **Status board**, **Pros & cons**, a timeline under the **Timeline** heading (**Vertical** or **Horizontal**), or a chart under the **Chart** heading (Bar, Stacked bar, Line, Pie, Doughnut). The current one has a check mark; one that doesn't fit the table's content is greyed out, with the reason on hover. Below it, always in the same order: **Heat-map ›**, **Add title…** and **Chart size ›** — each greyed out when it doesn't apply — then **Edit data** / **Copy**, then **Delete**.
- **Charts & Cards:** a chart (bar, stacked bar, line, pie, doughnut) or **Cards** (one stat card per row). A single click leaves a chart or Cards figure as it is; **double-click** it, or use **Edit data** on its right-click menu, to show its underlying table for editing — cells, plus the full cell menu — and it goes back to the chart/Cards, redrawn with the new values, on **Esc** or a click outside.
- **Chart details:** values can be written the way spreadsheets show them (`$12,400`, `12%`, `1.2k`, `(300)`); the value axis uses round steps with thousands separators (`10,000`, or `1.2M` above a million) and handles negative values. The chart's right-click menu adds **Add title…** (centred above a chart, a heading above Cards; also in the PDF) and, for charts, **Chart size ›** — Auto, Small, Medium or Full; Small and Medium keep their text at normal size.
- **Cards details:** each card shows its label (with a small square in the card's colour, or its icon if you picked one), then the value with its change beside it. **Show as › Cards** is offered for a table with 2 to 5 columns and 2–12 rows whose second column holds numbers (at least half of its filled cells; `1,240`, `12%`, `€1.2M`, `3.2 h`, `<2 s` all count). A later column written with signs or arrows is each card's **change** — `+5`, `-0.4%` or `▲ 8%` shows as a green ▲ or red ▼ pill (`0` stays neutral; `n/a`, dashes and empty cells are fine). Any other column (a note, an owner, a quantity) shows as a **detail line** under the value; with two detail columns, each line starts with its column header. Values and detail lines line up along each row of cards. A table that no longer fits after an edit shows as a plain table. Cards fill rows evenly (5 cards are 3 + 2, never 4 + 1) and print slightly tighter in the PDF.
- **Card icons & accents:** right-click a single card → **Card icon ›** (a grid of 25 icons in three groups — General: Time, Date, People, Goal, Done, Risk, Total, Growth, Cost; Systems: System, Architecture, ERP, Webshop, Integrations, API, Cloud, Security, Mobile, Code, Configuration; Logistics: Delivery, Warehouse, Location, Label, Report — names show on hover; or **No icon**) or **Accent colour ›** (Accent, Blue, Green, Orange, Purple, Red, Gray, or **Default** for the automatic colour). Both are picked by hand per card and stay with the card's label when rows are reordered.
- **Chips:** **Show as › Chips** on any two-column table shows each row as one pill — the first column as a short bold key, the second as its description (e.g. `ZN · Night Distribution`). Works on text-only tables that can't be charted, and carries through to the PDF; **Show as › Table** switches back. Chips and charts are mutually exclusive.
- **Progress bars:** **Show as › Progress bars** on a two- or three-column table: each row becomes a labelled bar. The second column is a percentage (`62%`, `62`, or a fraction like `0.62`); with a third column, the second is measured against it as a goal (31 of 50 → 62%; past the goal the bar is full and the number keeps counting, e.g. 120%). Bars turn green at 100%. **Show as table** goes back.
- **Timeline:** **Show as › Vertical** (under the Timeline heading) on a table whose first column holds dates (`2026-10-14`, `Oct 14, 2026`, `14 Oct`, `Oct 2026`), the second the event and an optional third a detail. Rows show on a vertical line in date order: done (before today, filled dot), **Next** (the first from today, highlighted) and upcoming (hollow dot); rows without a date (e.g. `TBD`) come last. Dates written without a year are placed in order but not marked done or upcoming. Carries through to the PDF. **Show as › Horizontal** lays the same milestones side by side on one line — date above, event and detail below — for short roadmaps of up to 8 rows (greyed out with more); it never splits across PDF pages.
- **Status board (open points):** **Show as › Status board** on a table with a **Status** column (headed Status, State or Stage, or holding status words) groups its rows into lanes — **Open**, **In progress**, **Blocked**, any other status as its own lane, then **Done** — with a count per lane. Each row becomes a card: the first other column is the item, columns headed **Owner** / **Assignee** and **Due** / **Deadline** / **Date** show under it (a due date in the past turns red unless the item is done), and the next column is a note. Common wordings are recognised (To do, WIP, On hold, Waiting, Closed, Resolved…). In the PDF the lanes print as columns, or one under another when there are 13+ items. A plain table with a Status column shows its statuses as coloured pills.
- **Folding:** the table dot beside a row folds its tables away; the fold is saved with the document, so it stays folded after a reload or a tab switch (the same goes for a row's image strip).
- **Position:** right-click a table or chart → **Position › Left / Center**. Left is the default; Center puts a plain table, a chart (most noticeable at Small or Medium size), chips, an inline list or a vertical timeline in the middle of its column, in the outline and the PDF. Cards, Status board, Pros & cons, Progress bars and a horizontal timeline already fill the width, so Position is greyed out for them ("Fills the full width"). Pictures already print centred in the PDF.
- **Show as says why, and offers a fix:** a display that doesn't fit the table stays in **Show as ›**, greyed out with a one-line reason under it ("Needs 2 columns; this has 3", "A timeline needs a date column"). Three fixes are offered when they apply: **Lanes by ‹column›** shows the table as a board with one lane per value of a column whose values repeat (e.g. Release / Phase), each row a card with its other columns, in neutral colours since they're groups, not statuses; **Use “‹column›” as the date** makes a timeline from a table whose dates aren't in the first column; **Move “‹column›” to column 2** moves a number column next to the labels when column 2 is text, since Cards, Progress bars and charts read their numbers from column 2 (a real column move, undoable). The choice is remembered on that column, so it moves with the column; switching to another display drops it, and Undo reverts it.
- **Pros & cons:** **Show as › Pros & cons** on a two-column table headed **Pros / Cons** (or Advantages / Disadvantages, For / Against, Benefits / Risks, Strengths / Weaknesses, Upsides / Downsides — either order) shows two cards side by side: pros in green with ticks, cons in red with crosses, each with a count. Empty cells are skipped. Prints side by side in the PDF.

### Extras on a plain table

- **Clean display:** a table shown as a table displays with horizontal rules only, a quiet small-caps header, and a faint "–" in empty or quote-only (`" "`) cells — in the outline and the PDF. Clicking in to edit shows the full grid, with nothing moving.
- **Group rows:** right-click a table → **Group rows** shows each run of repeated values in the first column once, as one cell spanning its rows (with "N rows" under it), and a heavier rule between groups. A value shaped like "code (name)" — `2001 (Centrallager Vejen)` — shows as a bold code over a muted name. It's display-only: the table itself and the editing grid keep every row's value. Greyed out when nothing in the first column repeats.
- **Total row:** right-click a table (or Cards) → **Total row** adds a row that adds up every number column — written like the column itself (`15 days` + `3 days` → `18 days`, `DKK 500.00` → `DKK 1,500.00`; `1 day` and `2 days` count as one unit). It's calculated each time the table shows, never stored as a row, so it can't go out of date as you add or edit rows; it prints in the PDF. Greyed out when no column can be added up (text, mixed units or percentages). A **typed** total row — the last row, starting with Total, Sum, Grand total or Subtotal — is recognised too: it gets the same footer look, stays last when you sort, and charts and the heat-map leave it out; if its number no longer matches the rows above, a small **Rows: 49 days** hint appears next to it (not in the PDF), and **Use calculated total** in the same menu replaces it with the calculated row (Undo brings it back). In **Cards** the total shows as one line under the cards rather than as a card.
- **Heat-map:** right-click a table shown as a table → **Heat-map ›** — **Higher is darker**, **Lower is darker** (for costs, churn and the like) or **Off**. Numeric cells are shaded by where they sit in their own column; text cells stay plain. The shading is worked out when the table is shown (editor and PDF), never saved into the table.
- **Ticks and crosses:** in a plain table, a column whose cells are mostly `✓` / `yes`, `✗` / `no` or `~` / `partial` shows them as green ✓, red ✗ and amber ~ icons (the original text is the tooltip); longer text like "Yes, from Q2" stays as written. Setting the column to any Column type (e.g. **Text**) turns this off.
- **Status pills and people:** a column headed Status (or set to Column type › Status) shows coloured status pills, and one headed Owner, Assignee, Who, Responsible or Lead (or set to Person) shows each name as a coloured chip — see **Column types** above. Like the heat-map and the icons, these are display only: the table you edit keeps its plain text, and clicking in to edit doesn't shift the columns.

## Hub — To-Dos

To-Dos lives at the app level rather than inside any single document — one shared list across your whole workspace, reachable from its single button in the app bar rather than per-document. (Earlier versions also had Meeting Notes, Journal, Library, and Recap panels here; all four were removed to keep the app focused on its core outline workflow — any data they left in browser storage is ignored, not deleted.)

- **To-Dos** (`Ctrl/Cmd+Shift+T`) — one shared task list across your whole workspace, not tied to any document or node. Supports priority, status, and due dates (with a Today/Tomorrow/Next week quick-pick popover), links, drag-to-reorder, quick-find, and an overdue-count badge. Filter by priority, status, and due date at once (Overdue/Today/Due later/No due date), and sort by priority, due date, or manual order. Select multiple open tasks to bulk-set priority/status/due date or bulk-complete/delete, each with its own Undo. Each task and sub-task has a Rewrite with AI button (when AI Capabilities is on). Typing `#tag` or `@name`/`@date`/`@status` directly in a task's text renders it as a colored chip with autocomplete. A task can either **repeat** (daily, weekdays, or weekly — completing it advances the due date instead of marking it done for good) or hold **sub-tasks** (a nested checklist with an n/m progress badge; the parent completes automatically once every sub-task is checked) — the two are mutually exclusive on the same task. Export the whole list as a PDF; Version History keeps the last 5 snapshots.
  - **Panel layout:** the header shows the title and open count, then **Search**, **Sort and filter** (one menu: sort order plus priority/status/due filters) and **⋯** (**Version history ›**: the last 5 versions, newest first, one click restores — restoring first saves the current list as a version — and **Save a version now**; then Export as PDF, Select or reorder tasks), then Maximize/Close. **Add a task** is a quiet row just below the header — click it, or press **N** while the panel has focus (outside a text field). Open tasks are grouped by status. **Now** holds the one task you chose to focus on: right-click a task → **Focus on this** (again → **Remove focus**); choosing another moves it, and nothing lands there on its own (no focus task, no Now section). Below it come **Doing** (In progress), **Up next** (no status) and **Waiting**; empty groups are hidden, and each keeps the list's sort order. There are three statuses — None, In progress, Waiting — and a Waiting task can carry a reason, **Needs review** or **Blocked**, set from the task menu. At rest a task is one line: the title (two lines at most) with a priority dot after it (High filled, Medium hollow, amber; click it to change the priority), and on the right a Waiting reason chip, subtask count (n/m), repeat and the due date ("Overdue · Oct 2" in red when late; click it to change the date). There is no edit card: click into the title or a subtask to type (the same white box shows only then), and everything else is in the **task menu**, opened by **⋯** on hover or by right-clicking the task — Priority and Status (every option shown, one click sets it; a Waiting task also shows its Reason), then due date, link, Add subtask and **Repeat ›** (its current setting on the right), Complete and Focus, **More ›** (Rewrite with AI, Duplicate, Copy, Move to top/bottom) and Delete. A task whose status changes moves to its new group. Clicking the subtask count, or a cut-off title, **unfolds** the task: the full title (no grey fill or highlight) and its open subtasks indented under it, and a quiet foot with **N done** (click to show them) and **+ Add subtask** (on hover); the task stays unfolded until you fold it again. A linked task shows a line under its title saying where it points (and, for one added from a follow-up, who raised it); clicking it goes there — to the row, or opens the web link; **Change link…** in the menu changes it. Completed tasks are one quiet line each, with a light tick and no chips.

On a narrow screen (below 768px), opening this file redirects once, on load, to **hub.html** — a separate, purpose-built mobile page rather than a cut-down view of this one. It covers **To-Dos** (with subtasks) only (AI features, PDF export, and version history all stay desktop-only). There's no app-bar header, bottom navigation, or floating compose pill — the only persistent chrome is a single sticky bar at the top with an inline "Add a task" affordance (tap it, type, Enter to add and keep typing the next one) and account access. The list is grouped the same way as the desktop To-Dos panel — **Now** for your focus task, then **Doing**, **Up next** and **Waiting**, each only appearing if it has anything in it — and each row shows the title with a priority dot and its due date on the right ("Overdue · …" in red), a Waiting reason as a chip, and repeat and subtask progress as quiet text. Tap a row for its detail sheet, where Priority and Status show every option so one tap sets it (a Waiting task also shows Reason), and **Focus on this** moves the task to Now. Swipe right to complete, swipe left to delete (instant, with a few seconds to Undo via the toast that appears, rather than a confirmation dialog interrupting every delete up front) — the same two-directions-one-gesture swipe Things 3 popularized. **Signing in is required there** — a phone is almost always a different browser from whatever device you last used, and local storage never crosses devices on its own; hub.html reads and writes the same `users/{uid}/meta/todos` document this file's own cloud sync already uses (Google or email sign-in, same account system as here), which is what actually bridges the two. It pulls once on sign-in (newer of cloud/local wins) and pushes after every change — no realtime listener, by design, for a page meant for short sessions rather than being left open for hours. There is no link back to this full editor from hub.html — its sign-in screen says outright that everything else needs a computer, rather than offering an escape hatch to a desktop UI that doesn't actually work well on a phone. The redirect check only runs on initial load, not on resize, so narrowing a desktop window mid-session never yanks the editor away from you.

hub.html has its own web app manifest (`hub-manifest.json`, `display: "standalone"`) separate from the root one this file uses — installing "Add to Home screen" from a phone launches straight into hub.html rather than bouncing through this file's redirect first. That manifest also registers hub.html as a **share target**: on Android (and any OS that honors PWA share targets — not currently iOS Safari), Sakura shows up in the system share sheet from other apps, and sharing a link or selected text creates a new to-do from it. It's GET-based, so it's link/text only, no shared files or images. Anyone who installed the Hub before this was added needs to reinstall it for the share-target registration to take effect.

## Tags, Focus & Backlinks

- **Tags** — select a node and click the tag icon, or right-click → Tags, to open a popover of existing document tags as toggleable chips (type a new name + Enter to add one). Tags render as `#chips` directly on the node row; clicking one filters the whole tree to that tag.
- **Backlinks** — while editing a node, type `@` to reference another node by name from a filtering dropdown. The reference saves as `[[Node name]]`, renders as a clickable link. Deleting a referenced node removes its `[[mentions]]` elsewhere automatically.
- **Focus** — right-click a node → Zoom in (or `Ctrl/Cmd+.`, or the toolbar's zoom icon) to show only that node and its descendants, with a breadcrumb trail back to the root. The zoomed node itself stays visible as the first row, so its own dots and inline objects (notes, tables, diagrams, images) can still be opened and closed. Exit with `Ctrl/Cmd+,` or by clicking the root crumb. Focus state is saved with the document (like fold state) and comes back when you reopen it, including across sessions.

## AI Features

AI features are entirely optional. Pick a mode at Settings → AI → Provider:

- **Sakura Hosted AI (beta)** — sign in (Google or email) and use it immediately, no key to find or paste. Requests go through a small Cloudflare Worker running Sakura's own credentials, capped by a daily per-account quota; the request text passes through that Worker to a third-party provider Sakura selects and isn't stored on either side. See "Data & privacy" below for the full breakdown against the BYOK path.
- **Bring your own key** — one of seven built-in providers (Gemini, Groq, Claude API, ChatGPT, OpenRouter, Cerebras, GitHub Models). Gemini, Groq, OpenRouter, and GitHub Models are free-tier friendly; Claude and ChatGPT require a paid account; Cerebras varies by account and model (its own "free trial" tier is time/credit-limited, not an ongoing free tier the way the others are — expect a payment-required error on some accounts). This is a fixed list; Sakura doesn't support a custom/self-hosted endpoint, since an open-ended one would defeat the point of the Content-Security-Policy allowlist that only these seven origins are on.

Both modes are available side by side in the same dropdown, and every AI feature below shares whichever one is currently active.

- **Rewrite** — toolbar AI ▾ → Rewrite node rewrites the selected node (or a batch, if multiple are selected, or just a highlighted portion of text). There's no whole-document rewrite. Right-click a note or remark line for its own Rewrite with AI, and each To-Do task/sub-task has one too. The rewrite prompt itself is fully customizable in Settings, with a one-click reset to the default grammar-and-spelling-only wording.
- **Auto-rewrite on commit** (off by default) — automatically runs Rewrite on a node as soon as you finish typing it (pastes/drops are excluded). Batches nodes into a single request after two minutes without further edits or once five are queued, rather than firing one request per node, to avoid burning through rate limits. Nodes under five words, checkbox items, headings, and text with `[[backlinks]]` or `` `code` `` are left alone. The only setting is the on/off switch. A status-bar chip shows the live queued/countdown/rewriting state and doubles as its own on/off toggle.
- **Generate outline** (`Ctrl/Cmd+Shift+O`) — describe a topic and get an AI-generated nested outline inserted into the current document (or a new blank one).
- **Provider fallback** — an optional toggle that automatically retries with the next configured provider (in your chosen order) if the active one fails for any reason other than a bad key, which always surfaces directly instead of silently falling back.
- **Usage today** — a local, best-effort request counter per provider, shown in Settings; it's a rough gauge only, not fetched from the provider, and can drift slightly from that provider's own reset clock.

## Quick Assist & Quick Insert

- **Quick Assist** (`Ctrl/Cmd+K` from anywhere, or click the search box in the header/status bar) is a combined command bar and search box. Plain-English commands work directly — "hide file explorer," "toggle dark mode," "toggle zen mode" — and toggle/search behavior is rule-based (a fixed phrase list), not AI, so it never improvises and needs no API key. Typing a bare word like "show," "hide," "toggle," or "run" lists everything of that kind; a category prefix ("notes: budget," "settings: dark," "todo: milk") narrows a search to one area — including Discussion, Diagrams, Tables and Images individually (`discussion:` — or `remark:`, `question:`, `qa:` — `diagram:`, `table:`, `image:`). Below commands, a separate **Run** row type covers one-off actions (new document, duplicate node, and the AI actions above: rewrite this node, generate outline) — always undoable, and never anything destructive. Below that, matching documents, node text, notes, tags, Discussion items (text, answer, Yes/No), Diagrams, table cells (the matching row), image captions, to-dos, and settings/help topics show up as **Go to** results.
- **Quick Insert** (`Ctrl/Cmd+Space` while actively editing text — anywhere: a node, the title field, a note, a thread entry or reply, a To-Do) opens a small labeled list of characters to insert — em dash, en dash, arrow, checkmark, cross mark, middle dot, date/time — which of them appear is configurable in Settings → Editing. Same menu, same shortcut, everywhere; it's deliberately just characters, not a second command bar, so it's never in competition with Quick Assist for the same key. Node-specific actions (Note, Tags, Add question, Rewrite, Version history) live on the right-click menu instead.

## Export & Import (PDF, OPML)

Export ▾ offers two formats, **PDF** and **OPML**; Import ▾ offers **OPML** only. (Earlier versions also exported Word, PowerPoint, Markdown, plain text, and Sakura Document `.sakura.json` files, copied the tree as text or an image from the Export menu, had a separate Print button, and imported Word `.docx` files, Sakura Document files, and pasted text from the Import menu; all of these were removed to keep the app focused on its core outline workflow. Whole-workspace backup/restore under Data & Backup is unaffected.)

- **Export ▾ → PDF** renders the current document headlessly and opens the browser's print dialog — choose "Save as PDF" there. It always renders the full document: folded sections, notes, linked Q&A and remarks, diagrams, images (with captions, at each image's chosen display size), and featured tables/charts all carry through (a table that runs over several pages repeats its header row on each one and never splits a row), with a Contents page (headings up to level 2 and section markers — a section like `[Release 2.4] Plan` shows as "Release 2.4 · Plan", each entry with a dotted leader and its page number, and clickable in the saved PDF) and a footer with the export date and page numbers on every page. Paper size is A4, or US Letter where that is the local default (US, Canada, Mexico, Philippines). A document with fewer than two sections or headings gets no Contents; with a cover page, Contents always has a page of its own; without one, up to eight entries print right under the title. A node's note prints directly under it, before its tables, charts and images. With a cover, the first body page starts with the first section rather than repeating the title. Optional cover page (Settings → Data & backup → Export & copy → "Cover page"): the title, author, word count and read time centred on the page, with the document's status as a stamp; it carries no footer but counts as page 1, so the footer's "Page x of y" always matches the PDF.
- **Untitled in the sidebar:** with no document open, the editor shows an empty "Untitled"; the sidebar lists it at the top, marked "not saved", until you type and it becomes a real document.
- **Leave out of export:** right-click a row → More → Row › **Leave out of export** to keep it, and everything under it, out of PDF and OPML exports (handy for internal notes in a document you share). The row stays as it is in the editor, apart from a small eye-with-a-slash icon after its text; click the dot, or the same menu item (now **Include in export**), to bring it back. Several selected rows can be set at once. The exported file never mentions what was left out; a toast after exporting says how many rows were skipped.
- **PDF branding** (Settings → Data & backup → Export & copy) adds a small attribution mark to the cover page and the bottom-right of every PDF page — on by default, with your own company/team name as an optional override for the default "SAKURA" wordmark ("PDF branding text").
- PDF exports (documents and the To-Dos list) use your current accent color by default; **Settings → Export & copy → "Use accent color in exports"** turns that off in favor of one fixed color, for consistent branding when the document is going to someone else rather than staying on your own screen.
- **Status stamp on PDFs:** when the document has a status (Draft, Review, Approved, Rejected), the exported PDF carries it as a coloured rubber-stamp mark on the cover page — or on the title block when the cover page is turned off. The in-app status pill never reaches someone reading the PDF. No status, no stamp.
- **PDF markers and footer:** markers print as their icon plus name (Agreed, Follow-up, Out of scope), since a printed page has no hover tip. Every page after the cover shows in its footer the document title and status on the left, the page number in the centre, and the export date on the right; the branding wordmark appears on the cover page only.
- **Export ▾ → OPML** saves the outline's structure, text, and each node's note (as an `_note` attribute) as an `.opml` file — always including folded sections. Images aren't part of OPML and are left out.
- The To-Dos panel exports to PDF only (⋯ → Export as PDF).
- **Copying nodes** (Ctrl/Cmd+C on selected nodes) puts them on the clipboard as both plain text and rich text — paste back into any Sakura document (the copied nodes' images and linked diagrams come along) or into another app. Folded children are always included in the copy.
- **Import ▾ → OPML** brings in an `.opml` outline file as a new document. Pasting a tree or text straight into the outline editor still works as ordinary editing.

## Theming & Appearance

- **Light/Dark theme** with an **Auto theme** mode: Off (manual only) or System (follows the OS/browser's dark-mode setting live). Manually overriding the theme while in System mode holds as a temporary override until the automatic value naturally catches up and matches it again.
- **Accent color** — six presets (Terracotta, the default, plus Teal, Indigo, Violet, Moss, and Amber), used for buttons, borders, and highlights (not node text itself).
- **Zen mode** (`Ctrl/Cmd+Shift+E`, or the maximize button by the editor) gives the outline the whole screen and always switches the browser to fullscreen; exiting fullscreen (Esc, F11, the browser's control) exits Zen too. Zen hides the toolbar, the tab bar and the file explorer (the file explorer's own toggle still works while in Zen); the app bar and status bar always stay visible.
- **Status bar, app bar and tab bar** are always shown (outside Zen, for the tab bar). The status bar shows word count and current depth, saved status, the Secure Storage lock chip while locked, the auto-rewrite chip while auto-rewrite is on, and Quick Assist when docked there. None of them are customisable.
- **Text size** (Settings → Appearance, 85–140%). Hovering a row's dot always shows its created/modified times, long lines always wrap, and notes/remarks/Q&A always start collapsed under their dot.
- Notes, remarks, and Q&A each show as a small dot next to their node; click a dot to expand that item as its own editable line(s) directly underneath the node. Right-click a note or remark line for a small menu (Rewrite with AI, Delete).

## Installing as an App (PWA)

Sakura can be installed as a standalone app (its own window, taskbar/dock icon, no browser chrome) via a bundled web app manifest (`display: "standalone"`) and service worker. Look for an install icon in the address bar (desktop Chrome/Edge) or "Add to Home screen" (mobile Chrome). Once installed and open, the app window's title bar color follows your in-app Light/Dark theme live.

The manifest's own `background_color`/`theme_color` (used for the brief install splash screen, and on Android the task-switcher card color) are a fixed warm off-white (`#f8f8f6`) matching the light theme — read by the OS/browser shell before any of the app's own code runs, so it can't follow a Dark-theme preference the way the live title bar does; the actual app window corrects to your real theme immediately after the splash.

The install icon itself is genuinely transparent (real alpha, not a flattened opaque square) so it renders correctly on any OS background — a dark taskbar, a colored tile — rather than showing as a flat square with wasted padding. A separate maskable variant is included for platforms (Android, some Windows contexts) that apply their own adaptive-icon crop shape on top.

## Account, Sync & Sharing

Signing in (Google or email, from the account button top-right) is entirely optional — everything above keeps working fully offline and locally without it. The sign-in screen (and hub.html's) has a **What gets stored?** fold-out: your documents, folders, To-Dos and settings and nothing else; no ads, analytics or tracking; no one else sees your documents unless you share one; Google sign-in shares only your name, email and photo. On the desktop screen, **Full privacy details** opens Settings → About → Privacy & data. Signing in does two things:

- **Sync** — your documents, folders, To-Dos, and settings sync to your account and follow you to another browser or device (newer-wins per item, not a field-level merge). A status-bar dot shows sync health. While signed in, this sync is your live, continuous off-device copy — there's nothing extra to set up.
- **Sharing** — share an individual document with another Sakura account as **Can view** or **Can edit**. A "Share" chip appears under a document's title once you're signed in; type a name or email to search (only accounts with **Profile visibility** set to Public, Settings → Account, Private by default, show up in results), pick a role, and click a result to share immediately. Documents shared with you appear in a **Shared** section in the file explorer, alongside who shared them and your access level. A bell icon next to the account button notifies you when someone shares something with you.

Sharing is deliberately simple in this version: access is per-document, not per-folder; a shared document opens as a normal tab but doesn't persist across a page reload the way your own documents do (reopen it from the Shared section); and there's no live co-editing — two people editing the same shared document at once still follow the same newer-wins sync model as your own devices do, not real-time collaboration.

## Data & Backup

Everything is stored locally in the browser, scoped to this exact file. Opening a different copy or a newer version of the file starts with empty storage — this is a browser limitation (local storage is partitioned per file URL), not a bug.

How your data is protected depends on whether you're signed in:

- **Signed in — automatic.** Your documents, folders, To-Dos, and settings sync to your account continuously (see [Account, Sync & Sharing](#account-sync--sharing) above). That is a live, off-device copy with nothing to configure.
- **Signed out — manual.** Everything lives only in this browser until you back it up yourself:
  - **Backup all data** (Settings → Data) saves everything — documents, folders, To-Dos, settings, and AI provider keys (encrypted if Secure Storage is on, plain text otherwise; handle the file like a password) — to a single downloadable JSON file. It's the only copy outside the browser, and the only reliable way to move *all* your data between different files, browsers, or computers.
  - **Restore from backup** (Settings → Data) reads one back and **replaces the entire app's contents** with the file's. For handing a single document to someone else, use the account-based **Share** chip under the title instead. Both live only in Settings, not as one-click shortcuts — Restore replaces everything, so it's worth the extra clicks. Restoring while signed in is guarded against overwriting newer synced work: the next sync pull reconciles against your account before anything local gets pushed back up. Backup files from older versions restore fine; settings for features that no longer exist are simply ignored.
  - **Undo last restore** (Settings → Data, appears only once you've restored) — every Restore first snapshots whatever's currently in the app, so this reverses the most recent restore if the file you picked turns out to have been the wrong one.

**Secure Storage** (Settings → Data) optionally encrypts your AI provider keys at rest with a passphrase only you know — in this browser and in backup files. Once set up, a status-bar chip appears while it's locked and a saved key for your active BYOK provider needs it; click to unlock. On Sakura Hosted AI the chip stays hidden — saved fallback keys only matter if a hosted call fails, so Sakura asks for the passphrase at that moment instead.

(Earlier versions also offered Cloud Backup to GitHub Gist / Google Drive, Auto-backup to a file on disk with Backup history, an automatic Local safety copy, a "Remind me to back up" status-bar chip, and a "Warn if this session isn't backed up" close-tab prompt. These were removed to keep backup simple: sign in for automatic sync, or back up manually.)

**Recommended workflow when moving to a new copy of this file:** Backup all data from the old copy, open the new copy, then Restore immediately.

## Feedback & Crash Reports

**Send feedback** (account menu, or Settings → Data) opens a small form — a message and an optional email — that goes straight to a write-only mailbox only Robin can read; nobody, including you, can read it back through the app. This is a deliberate, one-time exception to the no-network-call-to-Firebase-unless-you-sign-in principle above: sending it is its own explicit consent, the same as clicking Sign in with Google is.

**Automatic crash reports** (Settings → Data, off by default) does the same thing without asking each time: if something throws an uncaught error, it silently files a short report — the error message, the last few console errors leading up to it, and basic environment info (browser, URL) — capped at 10 reports per session with duplicates skipped. It's off by default specifically because it's the one thing in this app that would otherwise phone home without you asking; turning it on is that ask. Either path never includes document, note, or task content — only the error itself and where it happened.

## Known Limitations

- Storage is scoped per file URL. A renamed, moved, or re-downloaded copy of this file starts with empty storage — Backup all data / Restore is the way to carry data across.
- Signed out, nothing backs your data up automatically: take an occasional Backup all data, since browser storage alone can be cleared.
- Account sync (see [Account, Sync & Sharing](#account-sync--sharing)) is optional, newer-item-wins, and per-document — there is no real-time/live co-editing. Two people (or two of your own devices) editing the same document at the same moment still resolve by whichever save lands last, the same as any other sync conflict here, not a merge. Sharing itself is per-document, not per-folder, and a document shared with you doesn't stay open across a page reload — reopen it from the Shared section in the file explorer.
- AI features send node/selection text to a third-party provider — with your own key, straight from your browser to the provider you configured (review that provider's own data-handling terms if that matters); with Sakura Hosted AI, through Sakura's own server first, to a provider Sakura selects, using Sakura's credentials (not stored on that server either way — see Settings → About → Privacy & data in-app for the full breakdown). The in-app "Usage today" counter is a local approximation, not an authoritative quota reading, and Sakura Hosted AI is additionally capped by a real daily per-account quota enforced server-side.
- Below 768px, this file redirects to hub.html, which requires signing in (no local-only mode there — see Mobile Hub above for why) and covers To-Dos only — the outliner itself isn't reachable from a phone-sized screen at all. hub.html's sign-in screen points to a computer for all of that instead of offering a non-working link back here. This is an intentional, staged rollout, not a bug, but someone who's never signed in has no mobile Hub access until they do.

## Contributing

After cloning, run `sh scripts/setup-git-identity.sh` once — it sets the correct commit author and enables a pre-commit guard (`.githooks/pre-commit`) that blocks any commit made under a different email. This exists because a placeholder email used in an earlier session turned out to belong to someone else's real GitHub account and got silently listed as a contributor; the guard catches that before it happens again.

Starting a Claude session on this repo (including a fresh session after a usage limit, or from a different Claude account)? Paste `docs/handoff-prompt.md`'s fenced prompt block into the conversation — it has everything needed to pick up work with no other context.

### Deployment

This section covers how the maintainer's copy is built and published — it doesn't change anything about running Sakura yourself (see [Overview](#overview): still just an `.html` file you open in a browser, no build step required).

`www.sakura-notes.com` is published by `.github/workflows/deploy.yml`: every push to `main` runs `npm run build -w sakura-web` (a plain `vite build` — static assets like `sw.js`, both PWA manifests, and icons live in `web/public/`, Vite's own static-passthrough convention, so no custom copy step is needed) and publishes the result via GitHub Actions' native Pages deployment. There's no separate `dist/` branch or manual publish step; `web/index.html`/`web/hub.html` in the repo are the real source, and CI builds and serves them on every merge. See `docs/history/architecture-plan.md`'s "Deployment mechanism" and "Repo hygiene" sections for the full history of how this was verified before being switched on.
